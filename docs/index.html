The idea

A 60-rule standard that strips ambiguity out of text.

ASD-STE100 combines ~60 writing rules — short sentences, active voice, one instruction each — with a controlled dictionary where every approved word carries exactly one meaning. Ask a model to answer in STE and it mechanically drops the two things that make LLM prose hard to trust: hedging, and compound sentences that smuggle three claims into one.

Before

"In order to deploy the service, you'll first want to make sure that all of the environment variables have been properly configured, and then you can go ahead and trigger a new build, which should subsequently pick up the latest changes."

After — STE

Deploy the service:
1. Make sure you set all the environment variables.
2. Start a new build.
3. The build uses the latest changes.

Install

One command in Claude Code.

This repo is a Claude Code plugin and a one-plugin marketplace. Add it straight from GitHub:

/plugin marketplace add menonpg/ste-prompt
/plugin install ste-prompt@menonlab

Then rewrite anything on demand:

/ste rewrite the deploy steps above in Simplified Technical English
# or just ask — the skill triggers automatically

The rules

Flat text has nowhere to hide ambiguity.

  • Procedural sentences: 20 words max
  • One instruction per sentence
  • Use the active voice
  • Present tense for instructions
  • Start with the command verb
  • Always use articles ("the file")
  • Never use a noun as a verb
  • One meaning per approved word
  • One topic per paragraph
  • Vertical list for 3+ steps
  • obey not follow · use not utilize
  • make sure not ensure · about not approximately

Built for procedures, runbooks, and agent output — not for nuance or risk analysis, where the caveats are the content. Use it where ambiguity is the enemy.
